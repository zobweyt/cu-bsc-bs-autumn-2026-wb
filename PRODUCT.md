## Product Purpose

shop-mcp — MVP инициативы P2.1 «Подбор товаров WB во внешнем ИИ-ассистенте». Мок MCP-сервер магазина с интерактивным UI (MCP Apps): покупатель описывает запрос с несколькими условиями, ассистент подбирает товары из каталога и честно показывает, какие условия выполнены, собирает корзину и передаёт её в оформление WB. Граница MVP: подборка и корзина — в чате; подтверждение, оплата и чек — на стороне WB (в прототипе имитация).

Успех: сквозной сценарий «подбор по 3+ условиям → карточка → корзина → переход в оформление WB → статус → метрики» работает из чата через custom connector, а при отсутствии подходящего товара ассистент прямо говорит об этом.

## Positioning

Не текстовый каталог, а магазин как часть чата: карточки с кнопками, общая корзина и заказы между чатами (стор на сервере, а не в окне браузера), плюс бизнес-метрики воронки (время от первого поиска до оплаты, конверсии) отдельным тулом.

## Operating Context

- Хост: Claude (custom connector, Streamable HTTP, `POST /mcp`).
- Локально: Bun, `bun run dev` → `http://localhost:3000/mcp`; проверка — MCP Inspector.
- 9 тулов: search_products, show_product, cart_add, cart_update, show_cart, checkout, show_orders, show_order, show_stats; 6 ресурсов `ui://shop/*`.
- Связанный контекст курса: `cu/Семестр 1/Бизнес-студия` (команда «Тренды», WB).

## Capabilities and Constraints

- Каталог: 201 мок-товар, картинки — SVG-заглушки в data-URI. Характеристики (`specs`) есть у пилотной категории «периферия» (29 товаров); по остальным фильтр отвечает «нет данных».
- Оформление и оплата — на стороне WB; в прототипе переход имитируется, деньги не списываются. Статусы выводятся из времени (Оформлен в WB → Сборка → В пути → Доставлен). Заказ помечен источником «ассистент».
- Корзина, заказы и метрики живут в памяти процесса: общие для всех чатов, сбрасываются при рестарте/редеплое.
- UI — автономные single-file HTML без внешних запросов (требование песочницы хоста).
- Язык интерфейса — русский.
- Открыто (не решено): позже заменить мок-каталог на настоящий поиск; какой именно источник данных — не выбрано.

## Product Principles

1. Чат — место выбора, WB — место покупки: оформление и оплата не уходят в чат.
2. Подборка честная: только данные карточки, ✓/✗ по каждому условию, «подходящего нет» — прямо.
3. Любое действие доступно кнопкой, а не только словами.
4. Состояние общее: корзина и заказы принадлежат пользователю, а не окну чата.
5. Мок честный: всё ненастоящее подписано, цифры не выдаются за реальность.
6. Воронка измеряется: от первого поиска до оформления — отдельным инструментом, а не на глаз.
7. Хост правит темой и шириной: UI подстраивается под клиент, а не наоборот.
